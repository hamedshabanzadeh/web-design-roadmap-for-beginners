از طراحی در Figma تا ساخت یک سایت واقعی

هدف این مسیر این است که دیگر فقط «طرح سایت» نسازی و برای کدنویسی به شخص دیگری تحویل ندهی. باید بتوانی ایده را از وایرفریم شروع کنی، UI و UX را بسازی، در Figma طراحی کنی، با HTML و CSS پیاده‌سازی کنی، JavaScript اضافه کنی و در نهایت سایت را روی اینترنت منتشر کنی.

بعد Wireframe بکش

فعلاً رنگ و زیبایی مهم نیست. فقط مشخص کن Header کجاست، منو کجاست، Hero چه شکلی است، بخش خدمات کجاست، عکس‌ها کجا هستند و Footer چگونه است.

بعد UI را در Figma طراحی کن

Wireframe را تبدیل به طراحی واقعی کن و رنگ، فونت، عکس، Button، Card و بقیه اجزا را مشخص کن.

قانون جدید: فقط نسخه Desktop طراحی نکن. حداقل نسخه Desktop و Mobile را طراحی کن.
۲ Figma را حرفه‌ای‌تر یاد بگیرفقط طراحی نکن؛ ساختار درست بساز ⌄

فقط بلد بودن ابزارهای ظاهری Figma کافی نیست. باید ساختار طراحی حرفه‌ای را هم یاد بگیری.

  • Frame
  • Auto Layout
  • Components
  • Variants
  • Styles
  • Variables
  • Constraints
  • Responsive Design
  • Dev Mode

مثلاً Button را ده بار جداگانه طراحی نکن. یک Component بساز و حالت‌های مختلف آن را مشخص کن:

Default Hover Disabled

این طرز فکر بعداً در برنامه‌نویسی هم خیلی به دردت می‌خورد.

۳ دیگر برای کدنویسی از Figma عکس نگیرخود فایل Figma مرجع اصلی است ⌄

PNG یا PDF فقط برای نمایش طرح خوب است. برای ساخت سایت باید خود فایل Figma مرجع باشد.

مثلاً در Figma می‌بینی:

  • عرض: 1200px
  • فاصله: 32px
  • رنگ: #1264FF
  • Border Radius: 12px

بعد همین مشخصات را در CSS پیاده می‌کنی.

Figma → VS Code نه Figma → عکس → VS Code
۴ HTML را کاملاً مسلط شواسکلت و ساختار صفحه ⌄

قبل از رفتن سراغ چیزهای پیچیده، HTML را خوب یاد بگیر.

  • header
  • nav
  • main
  • section
  • article
  • footer
  • h1 تا h6
  • p
  • a
  • button

فقط تگ‌ها را حفظ نکن. باید بفهمی ساختار صحیح یک صفحه وب چیست.

مثلاً وقتی در Figma این بخش‌ها را می‌بینی:

ذهن تو باید سریع آن را به ساختار HTML تبدیل کند:

<header></header> <main> <section class="hero"></section> <section class="services"></section> <section class="about"></section> <section class="projects"></section> <section class="contact"></section> </main> <footer></footer>

۶ Responsive Design یاد بگیرسایت باید روی موبایل هم درست باشد ⌄

سایتی که فقط روی لپ‌تاپ درست نمایش داده شود، سایت کامل نیست.

باید سایت روی Desktop، Tablet و Mobile درست کار کند.

مثلاً اگر Desktop این باشد:

TEXT IMAGE

ممکن است در Mobile تبدیل شود به:

IMAGE TEXT BUTTON

برای این کار باید این موارد را یاد بگیری:

  • Media Query
  • Flex
  • Grid
  • درصد
  • max-width
  • min/max/clamp
  • Responsive Typography

۸ AI را فعلاً دستیار خودت کنکمک بگیر، اما یادگیری را دور نزن ⌄

در این مرحله می‌توانی از AI کمک بگیری، اما هنوز نباید کل طراحی یا کل سایت را به آن بسپاری.

قانون مهم: کدی که نمی‌فهمی وارد پروژه نکن و طرحی را که نمی‌توانی ارزیابی کنی فقط به خاطر اینکه AI ساخته، قبول نکن.

استفاده درست در این مرحله

  • توضیح یک مفهوم سخت در HTML، CSS یا JavaScript
  • پیدا کردن علت یک خطا
  • گرفتن بازخورد درباره طراحی خودت
  • توضیح خط‌به‌خط یک قطعه کد
  • پیشنهاد چند راه برای Responsive کردن یک بخش

استفاده اشتباه در این مرحله

  • «کل UI را برایم طراحی کن» و بدون بررسی قبول کردن خروجی
  • «کل سایت را بساز» و Copy/Paste کردن کد
  • رد شدن از JavaScript فقط چون AI می‌تواند کد بنویسد

AI در این مرحله باید نقش معلم، منتقد و دستیار را داشته باشد.

۹ اول یک سایت را خودت کامل بسازنقطه ورود به استفاده جدی از AI ⌄

قبل از اینکه سراغ تبدیل طراحی به کد با AI بروی، حداقل یک پروژه را خودت از ابتدا تا انتها انجام بده:

Wireframe → UI/UX → Figma → HTML → CSS → Responsive → JavaScript ساده

لازم نیست برنامه‌نویس حرفه‌ای شده باشی؛ اما باید بتوانی ساختار صفحه، CSS و رفتارهای ساده JavaScript را بفهمی و اشکال‌های معمول را پیدا کنی.

نقطه کنترل: اگر می‌توانی یک Landing Page یا سایت شرکتی Responsive را خودت بسازی و توضیح بدهی هر قسمت چگونه کار می‌کند، آماده‌ای AI را جدی‌تر وارد Workflow کنی.

قابلیت‌های AI و ابزارهای جدید Figma که باید بشناسی

Figma AI

چه کمکی می‌کند؟ برای سرعت دادن به بعضی کارهای طراحی، ایده‌پردازی و ویرایش در محیط Figma.

چه زمانی؟ وقتی خودت اصول UI، Auto Layout، Component و Responsive Design را می‌فهمی.

حواست باشد: پیشنهاد AI جای تصمیم طراحی و قضاوت UX را نمی‌گیرد.

Figma Make

چه کمکی می‌کند؟ می‌توانی با Prompt و طراحی موجود، ایده را سریع‌تر به یک تجربه یا Prototype قابل اجرا نزدیک کنی.

چه زمانی؟ برای آزمایش ایده، Prototype و سریع دیدن نتیجه.

حواست باشد: خروجی آماده به معنی خروجی نهایی و Production-ready نیست.

Dev Mode

چه کمکی می‌کند؟ فاصله بین طراحی و توسعه را کمتر می‌کند و مشخصات طراحی را برای پیاده‌سازی قابل استفاده‌تر می‌کند.

چه زمانی؟ وقتی می‌خواهی طراحی خودت را دقیق در HTML/CSS یا یک پروژه Front-end پیاده‌سازی کنی.

هدف: کمتر حدس بزن، بیشتر از ساختار واقعی طراحی استفاده کن.

Figma MCP + Coding Agent

چه کمکی می‌کند؟ ابزارهای کدنویسی AI می‌توانند اطلاعات ساختاری طراحی Figma را دریافت کنند و در پیاده‌سازی Front-end کمک کنند.

چه زمانی؟ بعد از اینکه می‌توانی خروجی HTML/CSS/JS را بخوانی و اصلاح کنی.

Workflow: Figma → MCP → Coding Agent → Code → بررسی و اصلاح توسط تو.

AI برای بررسی طراحی

چه کمکی می‌کند؟ می‌توانی از AI بخواهی درباره سلسله‌مراتب بصری، وضوح محتوا، Responsive بودن یا مشکلات احتمالی طراحی بازخورد بدهد.

بهترین استفاده: اول خودت طراحی کن، بعد AI را مثل یک منتقد دوم وارد کن.

AI برای یادگیری کد

چه کمکی می‌کند؟ خطا را توضیح می‌دهد، کد را خط‌به‌خط باز می‌کند و برای یک مسئله چند راه‌حل پیشنهاد می‌دهد.

بهترین استفاده: به جای گرفتن جواب آماده، از AI بخواه دلیل و منطق راه‌حل را هم آموزش دهد.

هدف نهایی: تو باید طراح و توسعه‌دهنده‌ای باشی که بدون AI هم اصول کار را می‌فهمد، اما با AI می‌تواند سریع‌تر ایده بسازد، Prototype بزند، کد تولید کند، اشکال پیدا کند و پروژه را جلو ببرد.
